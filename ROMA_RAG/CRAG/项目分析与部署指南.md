# CRAG 项目全面分析与部署指南

## 📋 项目概述

**CRAG (Corrective Retrieval Augmented Generation)** 是一个**可插拔的RAG增强框架**，旨在提高RAG系统的鲁棒性。它通过评估检索文档的质量，并根据置信度触发不同的知识检索策略。

### 核心特点

1. **可插拔设计**：CRAG可以作为插件无缝集成到各种RAG方法中
2. **智能评估**：使用轻量级检索评估器评估检索文档质量
3. **多策略检索**：根据评估结果触发不同的知识检索动作
4. **知识精炼**：通过分解-重组算法选择性聚焦关键信息

### 核心组件

#### 1. **检索评估器 (Retrieval Evaluator)**
- **模型**：基于T5的序列分类模型
- **功能**：评估检索文档与查询的相关性，返回置信度分数
- **输出**：置信度分数，用于决定后续动作

#### 2. **知识准备模块**

**a) 内部知识准备 (Internal Knowledge - Correct)**
- 对检索到的文档进行分解和精炼
- 过滤无关信息，保留关键内容
- 支持三种分解模式：
  - `selection`：不分解，直接使用
  - `excerption`：按句子边界分解
  - `fixed_num`：按固定词数分解

**b) 外部知识准备 (External Knowledge - Incorrect)**
- 当检索质量低时，通过Web搜索获取补充知识
- 使用OpenAI API进行问题重写
- 使用Google Search API (serper.dev) 进行搜索
- 支持两种模式：
  - `wiki`：优先访问Wikipedia相关页面
  - `all`：访问所有页面

**c) 组合知识准备 (Combined Knowledge - Ambiguous)**
- 结合correct和incorrect知识
- 用于中等置信度的情况

#### 3. **推理模块 (CRAG Inference)**

根据评估器的置信度分数，选择不同的知识源：

```
置信度 >= upper_threshold  → 使用 correct (内部知识)
置信度 >= lower_threshold  → 使用 ambiguous (组合知识)
置信度 < lower_threshold   → 使用 incorrect (外部知识/Web搜索)
```

## 🔌 CRAG作为插件的原理

### 重要说明：CRAG不包含检索系统

**关键理解**：CRAG项目本身**不包含检索系统**，它只对**已经检索好的结果**进行处理。

### 默认使用的检索数据来源

根据README和代码分析：

1. **默认数据来源**：项目推荐使用 [Self-RAG项目](https://github.com/AkariAsai/self-rag) 提供的**已检索好的评估数据**
   - 这些数据包含问题和对应的检索段落
   - 格式：`问题 [SEP] 检索段落`
   - 存储在 `data/数据集名/retrieved_psgs` 文件中

2. **CRAG的工作位置**：
   ```
   [检索系统] → 检索结果 → [CRAG评估和增强] → 优化文档 → LLM生成
   ```
   CRAG在检索**之后**、生成**之前**工作

3. **与Self-RAG的关系**：
   - Self-RAG提供了**检索结果数据**（不是检索系统本身）
   - CRAG可以使用任何检索系统的结果，不限于Self-RAG
   - 代码支持Self-RAG的模型格式（prompt格式），但也可以使用其他LLM

### 为什么CRAG是插件式的？

从代码架构可以看出，CRAG的核心思想是：

1. **不改变原有RAG的检索流程**：CRAG在检索**之后**工作
2. **增强检索结果**：对检索到的文档进行评估和优化
3. **灵活集成**：可以替换任何RAG系统的知识准备阶段
4. **不依赖特定检索系统**：可以使用任何检索方法的结果

### 工作流程对比

**传统RAG流程：**
```
查询 → 检索 → 文档 → LLM生成
```

**CRAG增强流程：**
```
查询 → 检索 → 文档评估 → [根据置信度选择知识源] → 优化后的文档 → LLM生成
```

### 如何集成到其他RAG方法？

CRAG可以集成到任何RAG系统，只需要：

1. **替换知识准备阶段**：将CRAG的知识准备模块插入到检索和生成之间
2. **使用评估器**：用CRAG的评估器评估检索结果
3. **动态选择知识源**：根据评估结果选择使用原始检索结果或增强后的知识

**示例集成方式：**
```python
# 伪代码示例
def enhanced_rag(query, retriever, generator):
    # 1. 原始检索
    retrieved_docs = retriever.retrieve(query)
    
    # 2. CRAG评估和增强
    confidence = evaluator.evaluate(query, retrieved_docs)
    if confidence >= threshold:
        enhanced_docs = internal_knowledge_prep(retrieved_docs)
    else:
        enhanced_docs = external_knowledge_prep(query)  # Web搜索
    
    # 3. 生成
    answer = generator.generate(query, enhanced_docs)
    return answer
```

## 🚀 部署与运行指南

### 环境准备

#### 1. 创建Python环境

```bash
# 使用conda创建环境（推荐Python 3.11）
conda create -n CRAG python=3.11
conda activate CRAG

# 安装依赖
cd CRAG
pip install -r requirements.txt
```

#### 2. 下载必要资源

**a) 下载评估器模型权重**
- 从 [Google Drive](https://drive.google.com/drive/folders/1CRFGsyNguXJwKSvFvJm_82GOOlkWSkW7?usp=drive_link) 下载评估器权重
- 解压到指定目录，例如：`./models/evaluator/`

**b) 下载生成器模型（可选）**
- 如果使用Self-RAG，下载 [Self-RAG LLaMA-2](https://huggingface.co/selfrag/selfrag_llama2_7b)
- 或使用其他兼容的LLM模型

**c) 下载评估数据（可选）**
- 从Self-RAG项目下载评估数据

#### 3. 配置API密钥

如果需要使用外部知识准备（Web搜索），需要配置：

```bash
# 设置环境变量或在脚本中配置
export OPENAI_KEY="your-openai-api-key"
export SEARCH_KEY="your-serper-dev-api-key"  # 从 https://serper.dev/ 获取
```

---

### 运行步骤

#### 步骤1：数据预处理

```bash
# 预处理数据集
bash run_data_preprocess.sh

# 或手动运行
cd scripts
python data_process.py --dataset popqa  # 或其他数据集
```

**输入数据格式：**
- `sources`：问题列表，每行一个问题
- `retrieved_psgs`：检索到的段落，格式：`问题 [SEP] 段落内容`

**输出：**
- `test_数据集名.txt`：处理后的测试文件

#### 步骤2：知识准备

这是CRAG的核心步骤，准备三种类型的知识：

```bash
bash run_knowledge_preparation.sh
```

**或分步执行：**

**a) 准备内部知识（Correct）**
```bash
cd scripts
python internal_knowledge_preparation.py \
  --model_path ../models/evaluator \
  --input_queries ../data/popqa/sources \
  --input_retrieval ../data/popqa/retrieved_psgs \
  --decompose_mode selection \
  --output_file ../data/popqa/ref/correct \
  --device cuda:0
```

**b) 准备外部知识（Incorrect）**
```bash
python external_knowledge_preparation.py \
  --model_path ../models/evaluator \
  --input_queries ../data/popqa/sources \
  --openai_key $OPENAI_KEY \
  --search_key $SEARCH_KEY \
  --task popqa \
  --mode wiki \
  --output_file ../data/popqa/ref/incorrect \
  --device cuda:0
```

**c) 准备组合知识（Ambiguous）**
```bash
python combined_knowledge_preparation.py \
  --correct_path ../data/popqa/ref/correct \
  --incorrect_path ../data/popqa/ref/incorrect \
  --ambiguous_path ../data/popqa/ref/ambiguous
```

#### 步骤3：运行CRAG推理

```bash
bash run_crag_inference.sh
```

**或手动运行：**

```bash
cd scripts
python CRAG_Inference.py \
  --generator_path /path/to/llm/model \
  --evaluator_path ../models/evaluator \
  --input_file ../data/popqa/test_popqa.txt \
  --output_file ../data/popqa/output/crag_output.txt \
  --internal_knowledge_path ../data/popqa/ref/correct \
  --external_knowledge_path ../data/popqa/ref/incorrect \
  --combined_knowledge_path ../data/popqa/ref/ambiguous \
  --task popqa \
  --method crag \
  --device cuda:0 \
  --ndocs 10 \
  --batch_size 8 \
  --upper_threshold 0.592 \
  --lower_threshold 0.995
```

**参数说明：**
- `--method`: `rag`（传统RAG）、`crag`（CRAG）、`no_retrieval`（无检索）
- `--ndocs`: 每个问题检索的文档数量
- `--upper_threshold`: 高置信度阈值（使用correct知识）
- `--lower_threshold`: 低置信度阈值（使用incorrect知识）

#### 步骤4：评估结果

```bash
bash run_eval.sh
```

**或手动运行：**

```bash
cd scripts
python eval.py \
  --input_file ../eval_data/popqa_longtail_w_gs.jsonl \
  --eval_file ../data/popqa/output/crag_output.txt \
  --metric match
```

## 📊 观察RAG效果的方法

### 1. 对比不同方法

运行三种模式进行对比：

```bash
# 传统RAG
python CRAG_Inference.py ... --method rag

# CRAG增强
python CRAG_Inference.py ... --method crag

# 无检索（基线）
python CRAG_Inference.py ... --method no_retrieval
```

### 2. 调整阈值参数

通过调整 `upper_threshold` 和 `lower_threshold` 观察效果：

```bash
# 更严格的阈值（更多使用外部知识）
--upper_threshold 0.7 --lower_threshold 1.0

# 更宽松的阈值（更多使用内部知识）
--upper_threshold 0.5 --lower_threshold 0.9
```

### 3. 查看中间结果

- 检查 `ref/correct`、`ref/incorrect`、`ref/ambiguous` 文件，了解知识准备的质量
- 查看评估器的置信度分数分布
- 对比不同分解模式的效果

### 4. 可视化分析

可以编写脚本分析：
- 不同置信度区间的准确率
- 知识源选择分布
- 错误案例分析

## 🔧 常见问题与解决方案

### 1. 内存不足

**问题**：运行大模型时GPU内存不足

**解决**：
- 使用 `--dtype half` 降低精度
- 减小 `--batch_size`
- 使用CPU模式（较慢）：`--device cpu`

### 2. API限制

**问题**：OpenAI API或搜索API达到限制

**解决**：
- 代码中已包含重试机制
- 可以分批处理数据
- 考虑使用代理或更换API服务

### 3. 模型下载失败

**问题**：从HuggingFace下载模型失败

**解决**：
- 使用镜像站点
- 手动下载后放到指定目录
- 使用 `--download_dir` 指定下载目录

### 4. 数据格式问题

**问题**：数据格式不匹配

**解决**：
- 检查数据文件编码（应为UTF-8）
- 确保 `[SEP]` 分隔符正确
- 参考示例数据格式

## 💡 最佳实践建议

1. **从小数据集开始**：先用少量数据测试流程
2. **逐步调试**：先运行数据预处理，再运行知识准备，最后推理
3. **保存中间结果**：知识准备耗时较长，保存结果避免重复计算
4. **监控资源使用**：注意GPU内存和API调用次数
5. **对比实验**：同时运行RAG和CRAG进行对比

## 📝 总结

### CRAG的核心价值

1. **可插拔性**：可以无缝集成到任何RAG系统
2. **智能评估**：自动评估检索质量
3. **动态增强**：根据评估结果选择最佳知识源
4. **知识精炼**：过滤无关信息，提高生成质量

### 适用场景

- ✅ 需要提高RAG系统鲁棒性的场景
- ✅ 检索质量不稳定的场景
- ✅ 需要结合内部和外部知识的场景
- ✅ 对生成准确性要求高的场景

### 不适用场景

- ❌ 实时性要求极高的场景（Web搜索有延迟）
- ❌ 无法访问外部API的场景
- ❌ 对成本敏感的场景（需要API调用）
